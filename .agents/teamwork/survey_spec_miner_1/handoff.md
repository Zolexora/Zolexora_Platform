## 2. Logic Chain

1. **Database Routing & Connection Architecture**:
   - *Observation*: `05-database-cluster-strategy.md` and `scripts/db/migrate-schemas.sql` consolidate 11 products into 4 Supabase instances (`core`, `commerce`, `business`, `ai_erp`).
   - *Logic*: Without Supavisor connection pooling (port 6543), microservice queries will exhaust the 15-connection free-tier limit of Supabase. Therefore, the connection router must strictly resolve credentials for the 4 projects, append schema search paths (e.g. `schema="ims"`), and route raw PostgreSQL queries to Supavisor port `6543` using `asyncpg`.
   - *Logic*: For MongoDB, a single shared M0 Atlas cluster hosts isolated databases `db_ai`, `db_tms`, `db_engage`, accessed via an asynchronous connection pool (`AsyncIOMotorClient`).
   - *Logic*: For R2, `boto3` generates S3 presigned URLs (`get_object` / `put_object`) using Cloudflare R2 credentials, ensuring zero egress fees.
   - *Logic*: When credentials are blank, connection attempts must degrade non-blockingly and return a `CONFIGURATION_DEGRADED` structured status rather than throwing unhandled exceptions.

2. **Capacity Telemetry & Autonomous Scaling**:
   - *Observation*: Hard free-tier limits are 500MB (PostgreSQL) and 512MB (MongoDB). `06-zero-cost-autonomous-architecture.md` specifies a 90% threshold trigger.
   - *Logic*: Telemetry background polling tasks must query `pg_database_size()` (for Postgres) and `db.stats()` (for MongoDB) on a periodic interval.
   - *Logic*: Hot table statistics must be gathered from `pg_stat_user_tables` (`idx_scan`, `seq_scan`, `n_tup_ins`, `n_tup_upd`, `n_tup_del`) and Mongo `$indexStats` to identify high-write and high-read tables.
   - *Logic*: When utilization reaches 90% (450MB on Postgres), the autonomous archiver calculates historical rows to migrate to a Cold Archive DB down to 40% capacity, checking `archive_exclusions.json` to respect pinned tables (`[ 🔒 Pin to Hot Storage ]`).

3. **Infisical Dynamic Account Lifecycle & Failover**:
   - *Observation*: `13-dynamic-account-router-and-monitoring.md` and `CREDENTIAL_STORAGE_PLAN.md` dictate dynamic $N+1$ account discovery without fixed account counts.
   - *Logic*: The router must parse `/shared/` (e.g. `/shared/firebase-pool/`) and `/platform-admin/` paths in Infisical.
   - *Logic*: When an account hits 90% of its quota limit, it transitions to `QUOTA_THROTTLED`, triggering automatic rollover to the next active account.
   - *Logic*: Missing credentials must dispatch structured JSON diagnostic events (`ROUTER_CREDENTIAL_MISSING`) and display alert banners without terminating the host process.

4. **Multi-Provider Email Architecture & MongoDB Archiving**:
   - *Observation*: Free tiers are capped per account (Resend 100/day, Brevo 300/day, SendGrid 100/day) and provider logs are ephemeral (Resend 1 day, SendGrid 3 days).
   - *Logic*: The Platform Admin FastAPI backend must expose a unified `POST /api/email/send` dispatch gateway. It tracks daily usage counters across provider accounts, skips accounts at ≥90% quota, and fails over across accounts and providers.
   - *Logic*: A nightly synchronization process extracts logs from provider APIs and archives them permanently into the MongoDB `email_logs` collection according to the defined JSON schema.

5. **Port Standardization & Compose Integration**:
   - *Observation*: `14-monorepo-port-allocation-registry.md` explicitly registers `ADMIN` on `3081` (Backend API), `3082` (Frontend Dev), and `5440` (`PLATFORM_ADMIN_POSTGRES_PORT`). Host port `5432` is strictly reserved.
   - *Logic*: `apps/platform-admin/compose.yaml` must expose frontend on `3082:3000`, backend on `3081:8000`, and include a local PostgreSQL service bound to `${PLATFORM_ADMIN_POSTGRES_PORT:-5440}:5432`. It must also adopt prebuilt image tags (`ghcr.io/zolexora/platform-admin-*`) with `pull_policy: missing`.

## 3. Caveats

1. **Current Codebase Gap**:
   - The current `apps/platform-admin/backend` implementation contains initial prototypes of `app/db/config.py`, `app/db/connections.py`, and `app/db/health.py`, but lacks the endpoint routes in `app/main.py`, email routing modules, capacity telemetry background workers, and dynamic account manager.
   - `requirements.txt` currently lacks required libraries: `asyncpg`, `motor`, `boto3`, `httpx`, `supabase`.
2. **Infisical CLI Runtime Availability**:
   - If developers run without the Infisical CLI logged in, the system must seamlessly fall back to local `.env` files located in `config/envs/platform-admin/` without failing startup.
3. **Supavisor Transaction vs. Session Pooling**:
   - Supavisor on port 6543 handles session and transaction pooling. When running DDL migrations or raw SQL requiring session state, port 5432 or direct connections may be used in staging, but runtime queries must route via 6543.
4. **Mocked Stubs in Existing Files**:

| 7 | Dynamic Account Discovery | `FIREBASE_ACTIVE_ACCOUNTS` contains slug `extra-prod`, but `FIREBASE_ACCOUNT_EXTRA_PROD_PROJECT_ID` is missing in Infisical | Router logs `ROUTER_CREDENTIAL_MISSING` critical diagnostic event, marks `extra-prod` as `DISCONNECTED`, and routes traffic only to remaining active accounts. |
